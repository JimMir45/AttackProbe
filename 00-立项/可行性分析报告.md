## 1. 分析概述

### 1.1 分析目的

本报告旨在从技术、资源、市场、运营四个维度评估 AttackProbe 安全有效性验证平台项目的可行性，为项目立项决策提供依据。

### 1.2 项目概要

| 维度 | 信息 |
|------|------|
| **项目名称** | AttackProbe 安全有效性验证平台 |
| **承建单位** | 卓望信息技术（北京）有限公司 |
| **目标客户** | 中国移动集团总部、31 个省公司、23+ 专业公司（60+ 客户实体） |
| **产品类型** | BAS（入侵与攻击模拟）平台 |
| **核心价值** | 安全防护效果量化评估、省公司能力横向对比、日志闭环验证 |

### 1.3 评估维度

| 维度 | 核心问题 | 评估标准 |
|------|---------|---------|
| **技术可行性** | 能否做出来？ | 技术成熟度、团队能力、架构合理性 |
| **资源可行性** | 有没有足够资源？ | 人力、预算、时间 |
| **市场可行性** | 有没有市场需求？ | 需求真实性、竞争态势、切入时机 |
| **运营可行性** | 能否持续运营？ | 部署运维、用例更新、服务支撑 |

### 2.3 核心模块技术方案

#### 2.3.1 攻击模拟引擎

| 方案 | 优势 | 劣势 | 推荐 |
|------|------|------|------|
| **基于 Nuclei 模板** | 30,000+ 现成模板、社区活跃、YAML 定义易扩展 | 偏漏洞扫描，需扩展攻击场景 | ✅ MVP 阶段 |
| **基于 Caldera** | ATT&CK 对齐、Agent 架构成熟 | 部署复杂、定制成本高 | V2.0 考虑 |
| **自研引擎** | 完全可控、深度定制 | 开发周期长、用例积累慢 | 不推荐 |

**推荐方案**：MVP 阶段以 Nuclei 模板为基础，扩展攻击场景能力；V2.0 参考 Caldera 架构增强 Agent 能力。

#### 2.3.2 日志闭环验证

| 技术点 | 方案 |
|--------|------|
| **日志采集** | Filebeat / Fluentd 采集 → Kafka 缓冲 → ES 存储 |
| **日志解析** | 预置 50+ 类安全设备日志解析规则（Grok/JSON） |
| **关联匹配** | 攻击任务 ID + 时间窗口 + 特征字段三维关联 |
| **验证判定** | 攻击 → 设备检测 → 告警生成 → 日志记录 四环节验证 |

#### 2.3.3 集团-省公司/专业公司两级架构

```
┌─────────────────────────────────────────────────────────────────────────┐
│                           集团管理节点                                     │

    ┌───┴─────────────────────────┐     ┌───────────────┴──────────────────┐
    │    省公司节点（主战型）        │     │    专业公司节点（主建型）          │
    │                              │     │                                  │
    ├───────────────┬──────────────┤     ├──────────────┬───────────────────┤

         31 个省公司（V1.0-V2.0）                23+ 专业公司（V1.5-V2.0）
```

**架构特点**：
- 省公司节点独立运行，支持无限期离线运行（上线后自动增量同步），面向"主战"场景（区域市场、本地业务）
- 专业公司节点按需部署，面向"主建"场景（能力建设、技术支撑）
- 数据向上汇聚，任务向下分发
- 支持任务/用例/配置导出至离线节点执行后导回结果（适用于网络隔离场景）
- 集团节点不直接执行攻击，仅做管理和汇聚
- 支持 31 个省公司节点 + 23 个专业公司节点横向扩展

### 2.4 技术风险与应对

| 风险 | 等级 | 应对措施 |
|------|------|---------|
| **用例库积累慢** | 中 | 直接导入 Nuclei 30,000+ 模板作为基础 |
| **日志格式多样** | 中 | 优先支持主流品牌（深信服、奇安信、启明星辰等），逐步扩展 |
| **信创适配工作量** | 中 | 数据库层抽象，通过适配器模式支持多数据库 |
| **攻击无害化保障** | 低 | 无害化 payload + 高风险用例隔离执行（降低审计风险） |
