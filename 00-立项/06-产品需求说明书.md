## 1. 产品概述

### 1.1 产品愿景

> **成为中国移动集团内部首选的安全有效性验证平台，支撑集团及 31 个省公司、23+ 专业公司实现安全防护能力的持续量化评估与闭环提升。**

*来源：[产品愿景与定位.md](./03-产品愿景与定位.md) 2.1节*

### 1.2 产品使命

> **通过自动化攻击模拟和日志闭环验证，将运营商安全防护从"被动响应"升级为"主动验证"，让安全投资的效果可衡量、可对比、可持续改进。**

*来源：[产品愿景与定位.md](./03-产品愿景与定位.md) 2.2节*

### 1.3 产品定位

| 维度 | 定义 |
|------|------|
| **目标市场** | 中国移动集团及 31 个省公司、23+ 专业公司（首选内部客户） |
| **核心品类** | 安全有效性验证平台（BAS） |
| **独特价值** | 集团-省公司/专业公司两级架构 + 日志闭环深度验证 + 运营商专属用例库 |

### 1.4 核心价值主张

| 价值 | 说明 | 量化指标 |
|------|------|---------|
| **安全防护效果"看得见"** | 每台安全设备的实际检测能力量化评分 | 设备检出率、策略有效性、安全评分 |
| **省公司能力"比得出"** | 31 个省公司安全防护能力横向对比 | 省公司排名、维度对比、趋势追踪 |
| **安全防护"改得好"** | 精准定位问题并提供修复建议 | 问题定位率、修复建议采纳率 |

*来源：[产品愿景与定位.md](./03-产品愿景与定位.md) 6.2节*

### 1.5 差异化竞争优势

基于竞品分析，AttackProbe 的核心差异化能力：

| 差异化维度 | 具体能力 | 对标优势 |
|-----------|---------|---------|
| **集团-省两级架构** | 集团统一管理、省公司独立运营、数据向上汇聚 | 国内 BAS 厂商均为单点架构 |
| **日志深度闭环** | 攻击→检测→告警→日志全链路验证，支持 50+ 类安全设备日志 | 闭环能力超越多数竞品 |
| **运营商专属用例** | IT 系统用例（MVP-V2.0）+ CT 网络/5G 核心网专属用例（V3.0 远期，依赖泰山队专家输入和 CT 网络接入权限） | 竞品无运营商 CT 侧场景 |
| **信创原生兼容** | 支持达梦/人大金仓数据库、麒麟/统信操作系统 | 满足集团信创硬性要求 |
| **省公司考核支撑** | 标准化评估体系、自动化报告、横向排名 | 竞品无此场景设计 |

*来源：[竞品深度分析报告.md](./02-竞品深度分析报告.md) 9.1节、[产品愿景与定位.md](./03-产品愿景与定位.md) 7.1节*

## 3. 核心业务场景

### 3.1 场景总览

基于运营商市场调研，AttackProbe 需支撑以下核心业务场景：

| 场景编号 | 场景名称 | 触发频率 | 优先级 | 覆盖版本 |
|---------|---------|---------|--------|---------|
| S1 | 护网攻防演练 | 年度/季度 | P0 | MVP |
| S2 | 安全设备有效性验证 | 月度/按需 | P0 | MVP |
| S3 | 省公司安全能力考核 | 季度/年度 | P0 | MVP |
| S4 | 等保合规验证 | 年度 | P1 | V1.0 |
| S5 | 新系统上线前安全验证 | 按需 | P1 | V1.0 |
| S6 | 0day/热点漏洞应急验证 | 事件驱动 | P1 | V1.0 |
| S7 | APT/勒索防御能力验证 | 季度 | P2 | V1.5 |
| S8 | 数据安全防护验证 | 季度 | P2 | V1.5 |
| S9 | 大模型应用安全验证 | 按需 | P3 | V2.0 |

*来源：[运营商市场调研报告.md](./01-运营商市场调研报告.md) 5.2节*

### 3.2 场景详细描述

#### S1: 护网攻防演练

| 维度 | 描述 |
|------|------|
| **场景背景** | HW 行动从年度演练趋向季度/月度，攻击手段日趋"AI+人工"智能化 |
| **用户痛点** | 护网前突击准备，平时缺少常态化验证；人工渗透测试成本高、覆盖面有限 |
| **使用流程** | 1) 选择护网专项用例集 → 2) 配置目标范围 → 3) 执行攻击模拟 → 4) 查看日志闭环结果 → 5) 生成护网准备报告 |
| **预期价值** | 护网前自动化验证防护能力，发现薄弱环节并提前整改 |
| **验收标准** | 支持护网常见攻击场景（Web渗透、横向移动、权限提升等），生成可交付的护网准备报告 |

#### S2: 安全设备有效性验证

| 维度 | 描述 |
|------|------|
| **场景背景** | 采购了大量安全设备，不确定是否真正生效；安全运营中心每天面对海量告警，真假难辨 |
| **用户痛点** | 安全设备形同虚设、告警疲劳、无法量化设备价值 |
| **使用流程** | 1) 选择目标安全设备 → 2) 选择验证用例 → 3) 执行攻击模拟 → 4) 采集设备日志 → 5) 关联分析 → 6) 输出设备检出率报告 |
| **预期价值** | 量化每台安全设备的实际检测能力，识别失效策略 |
| **验收标准** | 支持 WAF/IDS/IPS/NDR 等主流设备验证，日志闭环率 ≥80% |

#### S3: 省公司安全能力考核

| 维度 | 描述 |
|------|------|
| **场景背景** | 集团对 31 个省公司安全建设水平差异大，缺乏统一度量标准 |
| **用户痛点** | 省公司能力参差不齐、安全投资效果难衡量、缺乏横向对比数据 |
| **使用流程** | 1) 集团下发统一验证任务 → 2) 各省执行任务 → 3) 结果自动汇聚 → 4) 生成横向对比报告 → 5) 输出排名和改进建议 |
| **预期价值** | 统一评估体系，数据驱动安全决策 |
| **验收标准** | 支持 31 省并行验证、自动汇聚、横向排名、趋势分析 |

### 4.2 MVP 功能需求 (P0)

MVP 阶段聚焦核心能力，目标：3 个省公司试点部署。

#### 4.2.1 攻击模拟模块

| 需求编号 | 需求名称 | 需求描述 | 验收标准 |
|---------|---------|---------|---------|
| FR-MVP-001 | 用例库管理 | 支持 YAML 格式用例的导入、分类、检索 | 导入 Nuclei 模板 ≥5,000 条 |
| FR-MVP-002 | 用例分类 | 按 ATT&CK 战术、攻击类型、目标设备分类 | 支持三级分类体系 |
| FR-MVP-003 | 任务创建 | 创建攻击模拟任务，选择用例和目标 | 支持单次/周期性任务 |
| FR-MVP-004 | 任务执行 | 在省公司节点执行攻击模拟 | 支持并发执行，单任务 ≤1000 用例 |
| FR-MVP-005 | 执行监控 | 实时查看任务执行进度和状态 | 进度更新延迟 ≤5s |
| FR-MVP-006 | 结果记录 | 记录每条用例的执行结果（成功/失败/超时） | 结果可追溯、可导出 |

**攻击类型覆盖（MVP）**：

| 攻击类型 | 用例数量目标 | 说明 |
|---------|-------------|------|
| Web 漏洞利用 | 2,000+ | SQL注入、XSS、RCE、文件上传等 |
| 恶意流量模拟 | 1,000+ | 恶意域名访问、C2通信模拟 |
| 暴力破解 | 500+ | SSH/RDP/Web登录爆破 |
| 漏洞扫描绕过 | 500+ | WAF/IDS 绕过技术 |
| 信息收集 | 1,000+ | 端口扫描、服务识别、目录遍历 |

#### 4.2.2 日志闭环模块

| 需求编号 | 需求名称 | 需求描述 | 验收标准 |
|---------|---------|---------|---------|

## 10. 术语表

| 术语 | 英文 | 定义 |
|------|------|------|
| **BAS** | Breach and Attack Simulation | 入侵与攻击模拟，通过模拟真实攻击验证安全防护有效性 |
| **ATT&CK** | Adversarial Tactics, Techniques, and Common Knowledge | MITRE 提出的攻击者战术和技术知识库 |
| **日志闭环** | Log Correlation Loop | 验证攻击是否被检测、告警并记录到日志的完整链路 |
| **用例** | Test Case | 单个攻击模拟场景的定义，包含攻击方式、目标、预期结果 |
| **检出率** | Detection Rate | 安全设备成功检测到攻击的比例 |
| **TTP** | Tactics, Techniques, and Procedures | 战术、技术和程序，描述攻击者的行为模式 |
| **APT** | Advanced Persistent Threat | 高级持续性威胁，有组织的长期定向攻击 |
| **DLP** | Data Loss Prevention | 数据泄露防护 |
| **EDR** | Endpoint Detection and Response | 终端检测与响应 |
| **NDR** | Network Detection and Response | 网络检测与响应 |
| **SOC** | Security Operations Center | 安全运营中心 |
| **SOAR** | Security Orchestration, Automation and Response | 安全编排自动化与响应 |
| **信创** | Xinchuang | 信息技术应用创新，国产化替代 |
