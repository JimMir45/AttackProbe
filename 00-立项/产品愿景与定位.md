## 2. 产品愿景与使命

### 2.1 产品愿景

> **成为中国移动集团内部首选的安全有效性验证平台，支撑集团及 31 个省公司、23+ 专业公司实现安全防护能力的持续量化评估与闭环提升。**

### 2.2 产品使命

> **通过自动化攻击模拟和日志闭环验证，将运营商安全防护从"被动响应"升级为"主动验证"，让安全投资的效果可衡量、可对比、可持续改进。**

### 2.3 产品名称

| 维度 | 内容 |
|------|------|
| **中文名** | AttackProbe 安全有效性验证平台 |
| **英文名** | AttackProbe - Security Effectiveness Validation Platform |
| **命名释义** | Attack（攻击模拟）+ Probe（探测验证），寓意通过模拟攻击探测安全防护的真实有效性 |

### 2.4 产品口号

> **"验攻知防，度量安全"**

释义：通过验证攻击来了解防御效果，用量化手段度量安全水平。

## 4. 核心痛点与需求

### 4.1 集团层面痛点

| 痛点 | 现状 | 期望 |
|------|------|------|
| **省公司能力参差不齐** | 31 个省公司安全建设水平差异大，缺乏统一度量标准 | 统一评估体系，横向可比，动态排名 |
| **安全投资效果难衡量** | 每年投入大量安全预算，但缺乏效果量化手段 | 投资效果可视化，数据驱动安全决策 |
| **护网准备缺乏持续性** | 护网前突击准备，平时缺少常态化验证 | 从年度突击转向持续验证 |
| **安全数据孤岛** | 各省安全数据分散，无法统一汇聚分析 | 集团统一视图，省公司数据实时汇聚 |

### 4.2 省公司层面痛点

| 痛点 | 现状 | 期望 |
|------|------|------|
| **安全设备形同虚设** | 采购了大量安全设备，不确定是否真正生效 | 验证每台安全设备的实际防护效果 |
| **告警疲劳** | 安全运营中心每天面对海量告警，真假难辨 | 降低误报率，精准识别有效告警 |
| **人工渗透测试成本高** | 依赖外部红队服务，频次低、覆盖面有限 | 自动化验证，降低人力依赖 |
| **资产底数不清** | 老旧系统"四无"（无理、无使用、无防护、无必要）问题 | 资产探测与风险关联 |
| **网络隔离粗放** | 内网扁平化，纵深防御薄弱 | 验证横向移动防护能力 |

## 6. 核心价值主张

### 6.1 价值公式

```
AttackProbe 价值 = 安全防护效果可视化 × 省公司能力量化对比 × 持续验证闭环提升
```

### 6.2 三大核心价值

#### 价值一：安全防护效果"看得见"

| 指标 | 说明 |

### 8.5 安全评分体系设计

基于等保 2.0、MITRE ATT&CK Evaluations 和 BAS 竞品评分模型研究，设计 AttackProbe 省公司安全能力评分体系。

#### 8.5.1 评分维度设计

采用 **4+3 维度模型**：4 个核心维度 + 3 个增强维度。

**核心维度（权重 80%）**：

| 维度 | 权重 | 评估内容 | 对应等保要求 |
|------|------|---------|-------------|
| **边界防护** | 25% | WAF/IDS/IPS/防火墙检出率、拦截率 | 安全区域边界 |
| **应用安全** | 20% | Web 漏洞防护、API 安全、中间件防护 | 安全计算环境 |
| **数据保护** | 20% | DLP 检测率、数据外泄防护、加密有效性 | 数据安全 |
| **检测响应** | 15% | SOC 告警覆盖率、MTTR、日志完整性 | 安全管理中心 |

**增强维度（权重 20%）**：

| 维度 | 权重 | 评估内容 |
|------|------|---------|
| **ATT&CK 覆盖** | 10% | 14 战术、200+ 技术的检测覆盖率 |
| **APT 防御** | 5% | 针对主要 APT 组织 TTP 的防御有效性 |
| **合规达标** | 5% | 等保测评结果、整改完成率 |

#### 8.5.2 评分计算方法

**单项评分公式**：
```
单项得分 = (成功检测用例数 / 总测试用例数) × 100
```

**综合评分公式**：
```
综合评分 = Σ(维度得分 × 维度权重) × 调整系数
```

**调整系数**：
- 误报率惩罚：误报率 > 10% 时，系数 = 1 - (误报率 - 10%) × 0.5
- 响应时效奖励：MTTR < 行业基准时，系数 = 1 + (基准 - MTTR) / 基准 × 0.1

#### 8.5.3 评级标准

| 等级 | 分数范围 | 说明 | 建议 |
|------|---------|------|------|
| **A（优秀）** | 90-100 | 全面领先，可作为标杆 | 持续保持，分享经验 |
| **B（良好）** | 80-89 | 整体良好，个别待提升 | 针对性优化弱项 |
| **C（合格）** | 70-79 | 基本达标，存在短板 | 制定整改计划 |
| **D（待改进）** | 60-69 | 多项不足，需重点关注 | 紧急整改，限期达标 |
| **E（不合格）** | <60 | 严重不足，存在重大风险 | 立即整改，专项督办 |

#### 8.5.4 ATT&CK 覆盖率计算

基于 MITRE ATT&CK Evaluations 方法论：

| 检测级别 | 定义 | 得分权重 |
|---------|------|---------|
| **Technique** | 检测到具体攻击技术 | 100% |
| **General** | 检测到异常但未识别技术 | 60% |
| **Tactic** | 仅检测到战术级行为 | 40% |
| **None** | 未检测到 | 0% |

**ATT&CK 覆盖率计算**：
```
覆盖率 = Σ(检测技术数 × 检测级别权重) / (总测试技术数 × 100%)
```

#### 8.5.5 省公司排名机制

| 排名类型 | 周期 | 用途 |
|---------|------|------|
| **综合排名** | 月度 | 整体安全能力对比 |
| **维度排名** | 月度 | 单项能力对比（边界、终端等） |
| **进步排名** | 季度 | 能力提升幅度对比 |
| **专项排名** | 按需 | 护网、专项检查结果对比 |

| **集团安全大模型** | 对接 AI 能力，智能分析验证结果 | 自动化修复建议，降低人工分析成本 |
| **威胁情报平台** | 获取最新威胁情报，更新用例库 | 保持用例库时效性 |
| **泰山队** | 支撑红队演练，提供自动化工具 | 提升护网效率，减少重复工作 |

### 9.3 中立性定位

| 原则 | 说明 |
|------|------|
| **专注验证** | 只做安全有效性验证，不做安全防护产品 |
| **公正评估** | 对所有品牌安全设备一视同仁，客观呈现检测能力 |
| **数据驱动** | 评估结果基于客观数据，而非主观判断 |
| **独立于防护** | 与启明星辰的关系是"验证者"而非"竞争者" |

> **关键定位**：启明星辰是"造盾"的，AttackProbe 是"验盾"的。只有独立于防护产品的第三方验证，才能保证评估结果的公正性和可信度。
