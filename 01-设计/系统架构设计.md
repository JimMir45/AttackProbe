## 1. 设计原则

基于 PRD 第6节技术约束和技术栈评估结论，系统设计遵循以下原则：

| 原则 | 说明 | 实践 |
|------|------|------|
| **两级分离** | 集团与省公司/专业公司职责分离、数据隔离 | 集团汇聚统筹，省公司/专业公司独立执行 |
| **离线自治** | 省公司节点支持离线运行 | 本地数据存储，上线后增量同步 |
| **部署简化** | 省公司单机场景，降低运维门槛 | Docker Compose 一键部署 |
| **数据库兼容** | 支持多种国产数据库 | GORM 适配层 + PG 兼容模式 |
| **引擎可插拔** | 攻击引擎支持扩展 | Executor 接口抽象，支持 Nuclei/Python/LLM |
| **信创优先** | 满足国产化要求 | 国密算法、国产数据库、国产操作系统 |

### 4.2 节点职责划分

| 职责 | 集团节点 | 省公司/专业公司节点 |

| **用例管理** | 统一用例库、版本管理 | 同步用例库、本地缓存 |
| **执行引擎** | 不执行攻击 | 执行攻击模拟 |
| **日志采集** | 汇聚各节点日志 | 采集本地安全设备日志 |
| **评分计算** | 全网评分、横向对比 | 本节点评分 |
| **报告生成** | 全网报告、对比报告 | 本节点报告 |
| **数据存储** | 全网汇聚数据 | 本节点数据 |
| **离线能力** | 要求在线 | 支持离线运行 |

### 4.4 节点定义与协作机制

#### 4.4.1 节点定义

**节点（Node）** 是 AttackProbe 平台的独立部署单元，每个节点包含完整的运行环境：

```
┌─────────────────────────────────────────────────────────────────────────┐
│                        节点（Node）定义                                   │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  一个节点 = 一个独立的 AttackProbe 部署实例                               │
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │                      节点组件构成                                 │   │
│  │                                                                  │   │
│  │  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐           │   │
│  │  │ API 服务  │ │ Web 前端  │ │ 攻击引擎  │ │ 判定引擎  │           │   │
│  │  └──────────┘ └──────────┘ └──────────┘ └──────────┘           │   │
│  │                                                                  │   │
│  │  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐           │   │
│  │  │PostgreSQL│ │  Redis   │ │    ES    │ │ Filebeat │           │   │
│  │  │ (业务库)  │ │ (队列)   │ │ (日志库) │ │ (采集器) │           │   │
│  │  └──────────┘ └──────────┘ └──────────┘ └──────────┘           │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  节点特征：                                                              │
│  • 独立运行：每个节点可独立完成攻击模拟、日志闭环、报告生成                 │
│  • 数据自治：本地存储所有业务数据，不依赖外部节点                          │
│  • 离线能力：支持完全离线运行（省公司/专业公司节点）                       │
│  • 统一接口：所有节点使用相同的代码和 API，通过配置区分角色                 │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

| 节点类型 | 角色定位 | 部署数量 | 核心职责 |
|---------|---------|---------|---------|
| **集团节点** | 控制平面 | 1 | 全网统筹、任务下发、数据汇聚、横向对比 |
| **省公司节点** | 数据平面 | 31 | 本省攻击执行、日志采集、结果上报 |
| **专业公司节点** | 数据平面 | 23+ | 本单位攻击执行、日志采集、结果上报 |

**关键区别**：
- **集团节点不执行攻击**：集团节点是管控中心，不直接对目标发起攻击模拟
- **省公司/专业公司节点执行攻击**：实际的攻击模拟均由省公司/专业公司节点在本地网络完成

### 11.3 性能优化策略

| 优化点 | 策略 |
