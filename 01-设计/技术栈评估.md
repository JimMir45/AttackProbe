## 1. 评估原则

基于 PRD 第6节技术约束和第5.4节兼容性需求，本评估遵循以下原则：

| 原则 | 说明 | PRD 来源 |
|------|------|---------|
| **信创优先** | 优先选择支持国产操作系统、国产数据库、国密算法的技术方案 | 5.3、5.4 |
| **运维简化** | 省公司单机部署场景居多，部署和运维应尽量简单 | 6.4 |
| **成熟稳定** | 优先选择经过大规模生产验证的开源组件 | 6.1 |
| **生态完善** | 中文文档、社区活跃度、国内案例 | 6.1 |
| **跨平台** | 同时支持 x86_64 和 ARM64（鲲鹏/飞腾） | 5.4 |

## 2. 后端框架选型

### 2.1 候选方案对比

| 维度 | Go + Gin | Java + Spring Boot | Python + FastAPI |
|------|----------|-------------------|-----------------|
| **性能** | 高，编译型语言，低内存占用 | 中高，JVM 启动慢、内存占用大 | 中，GIL 限制并发 |
| **部署** | 单文件部署，无运行时依赖 | 需 JVM 环境，JAR 包较大 | 需 Python 环境 |
| **并发模型** | Goroutine，轻量级协程 | 线程池，资源消耗较大 | asyncio，受 GIL 限制 |
| **信创兼容** | 原生交叉编译 ARM64 | 需适配 ARM64 JDK | 依赖 C 扩展需编译 |
| **Nuclei 集成** | 原生 Go 调用，零开销 | 需进程间通信调用 | 需进程间通信调用 |
| **开发效率** | 中高，语法简洁 | 中，生态成熟但冗长 | 高，语法灵活 |
| **运维成本** | 低，单文件更新 | 高，JVM 调优复杂 | 中，依赖管理复杂 |

### 2.2 选型结论：Go + Gin

**核心理由**：

1. **Nuclei 原生集成**：Nuclei（ProjectDiscovery）使用 Go 开发，AttackProbe 基于 Nuclei 引擎封装可直接以 Go 库的方式调用，避免进程间通信开销
2. **单文件部署**：编译为单个二进制文件，省公司节点部署无需额外运行时环境
3. **ARM64 原生支持**：`GOARCH=arm64` 即可交叉编译鲲鹏/飞腾版本
4. **低资源占用**：省公司节点通常资源有限，Go 的内存占用远低于 Java

**版本要求**：Go 1.22+（支持增强路由、改进 GC）

**Web 框架选择 Gin 的理由**：
- GitHub Star 80K+，国内使用最广泛的 Go Web 框架
- 性能优异，httprouter 路由引擎
- 中间件生态丰富（CORS、JWT、日志、限流）
- 与 GORM 配合成熟

## 3. 前端框架选型

### 3.1 候选方案对比

| 维度 | Vue 3 + Element Plus | React + Ant Design | Angular + NG-ZORRO |
|------|---------------------|-------------------|-------------------|
| **中文生态** | 优秀，国内占有率最高 | 良好，国际主流 | 一般，国内使用较少 |
| **组件库质量** | Element Plus 企业级 | Ant Design 企业级 | NG-ZORRO 企业级 |
| **学习曲线** | 低，Options/Composition API | 中，JSX + Hooks | 高，TypeScript + RxJS |
| **后台管理适配** | 优秀，大量模板和方案 | 优秀，Pro 方案成熟 | 良好 |
| **表格/图表** | Element Plus Table + ECharts | Ant Table + ECharts | 需额外集成 |

### 3.2 选型结论：Vue 3 + Element Plus

**核心理由**：

1. **国内企业级后台首选**：Element Plus 在中国企业后台管理系统中使用最广泛，组件设计贴合国内使用习惯
2. **表格与表单能力**：AttackProbe 以任务管理、结果展示、报告查看为主要交互，Element Plus 的 Table、Form、Descriptions 组件开箱即用
3. **ECharts 集成**：安全评分雷达图、趋势折线图、省公司对比柱状图等可视化需求，ECharts 为最佳选择
4. **Vite 构建**：开发体验好，HMR 快速，构建产物体积小

**版本要求**：Vue 3.4+、Element Plus 2.4+、Vite 5+

**前端关键依赖**：

| 依赖 | 用途 |
|------|------|
| `vue-router` 4.x | 路由管理 |
| `pinia` 2.x | 状态管理 |
| `axios` 1.x | HTTP 客户端 |
| `echarts` 5.x | 数据可视化 |
| `@vueuse/core` | 组合式工具函数 |

## 4. 数据库选型

### 4.1 选型背景

PRD 明确要求支持三种数据库：PostgreSQL（主选）、达梦 DM8、人大金仓（信创替代）。

| 需求来源 | 要求 |
|---------|------|
| PRD 6.1 | 主选 PostgreSQL，信创替代达梦 DM8 |
| PRD 5.4 | 兼容 PostgreSQL 13+、达梦 DM8、人大金仓 |
| PRD 6.5 | 适配器模式支持 PG/DM8/KingBase |

### 4.2 候选方案对比

| 维度 | PostgreSQL | 达梦 DM8 | 人大金仓 KingbaseES |
|------|-----------|---------|-------------------|
| **定位** | 主选数据库 | 信创首选 | 信创补充 |
| **开源** | 开源 | 商业（有国产化要求的项目可免费） | 商业 |
| **PG 兼容** | 原生 | 支持 PG 兼容模式 | 高度兼容 PG |
| **部署** | 简单，包管理器安装 | 需安装包 | 需安装包 |
| **ARM64** | 原生支持 | 支持鲲鹏 | 支持鲲鹏/飞腾 |
| **安全可靠测评** | N/A（国际开源） | ✅ 已通过 | ✅ 已通过 |
| **JSON 支持** | 原生 JSONB | 兼容 JSON | 兼容 JSONB |
| **运营商案例** | 中国联通、中国电信 | 中国移动多个项目 | 央企、政务 |

> 安全可靠测评数据来源：[中国信息安全测评中心](https://www.itsec.gov.cn)

### 4.3 选型结论

| 环境 | 数据库 | 理由 |
|------|-------|------|
| **开发/测试** | PostgreSQL 16 | 本地开发零成本，功能完整 |
| **生产（通用）** | PostgreSQL 13+ | 开源免费，JSONB 对日志关联有优势 |
| **生产（信创）** | 达梦 DM8 | 中国移动信创项目首选，PG 兼容模式可降低适配成本 |
| **生产（信创备选）** | 人大金仓 KingbaseES V8 | 高度兼容 PG，部分省公司已有采购 |

### 4.4 多数据库兼容方案

```
┌─────────────────────────────────────────────────────────────────┐
│                        应用层 (Go)                                │
├─────────────────────────────────────────────────────────────────┤
│                         GORM ORM                                  │
│                  (统一 API，屏蔽底层差异)                          │
├──────────────────┬──────────────────┬───────────────────────────┤
│  PostgreSQL      │   达梦 DM8       │   人大金仓                  │
│  Driver          │   Driver         │   Driver                   │
│  (gorm/postgres) │ (dm-go + 适配层) │  (PG 兼容 Driver)          │
├──────────────────┼──────────────────┼───────────────────────────┤
│  PostgreSQL 13+  │   达梦 DM8       │   KingbaseES V8           │
│  (主选)          │   (PG 兼容模式)   │   (PG 兼容模式)            │
└──────────────────┴──────────────────┴───────────────────────────┘
```

**兼容性约束**：
- SQL 语法限制在 PostgreSQL 13 兼容子集
- 避免使用 PG 特有扩展（如 PostGIS、pg_trgm），除 JSONB 外
- 达梦 DM8 开启 PG 兼容模式（`COMPATIBLE_MODE=PG`），最大化兼容
- 人大金仓原生兼容 PG 语法，适配成本最低
- GORM 迁移工具统一建表，配置文件切换数据库类型

**配置示例**：
```yaml
# 开发/生产 (PostgreSQL)
database:
  driver: postgres
  dsn: "host=localhost port=5432 user=attackprobe dbname=attackprobe sslmode=disable"

# 信创 (达梦 DM8, PG 兼容模式)
database:
  driver: dm
  dsn: "dm://SYSDBA:password@dmserver:5236/ATTACKPROBE"

# 信创 (人大金仓)
database:
  driver: kingbase
  dsn: "host=kbserver port=54321 user=attackprobe dbname=attackprobe"
```

## 5. 消息队列选型

### 5.1 选型背景

PRD 6.1 指定 Redis 作为消息队列，用于任务调度和结果回传。

### 5.2 候选方案对比

| 维度 | Redis | RabbitMQ | Kafka |
|------|-------|----------|-------|
| **定位** | 内存数据库 + 轻量队列 | 专业消息队列 | 分布式流处理 |
| **部署复杂度** | 单节点即可 | 需 Erlang 环境 | 需 ZooKeeper/KRaft |
| **省公司场景** | 适合，资源占用少 | 偏重 | 过重 |
| **功能** | 队列 + 缓存 + 分布式锁一体 | 纯消息队列 | 流处理 |
| **ARM64** | 原生支持 | 支持 | 支持 |
| **Go 客户端** | go-redis，成熟稳定 | amqp091-go | sarama/confluent |

### 5.3 选型结论：Redis

**核心理由**：

1. **一体多用**：任务队列（List/Stream）、结果缓存（Hash）、分布式锁（RedLock）、节点心跳（Expire）四合一，省公司只需部署一个 Redis 实例
2. **资源占用少**：单实例内存占用可控，适合省公司有限资源场景
3. **部署简单**：Docker 单容器部署，无额外依赖
4. **Go 生态成熟**：`go-redis/redis` 库 Star 20K+，API 完善

**版本要求**：Redis 7.0+（支持 Redis Functions、改进 ACL）

**使用场景规划**：

| 场景 | Redis 数据结构 | 说明 |
|------|---------------|------|
| 任务队列 | Stream | 任务下发、执行状态追踪 |
| 结果缓存 | Hash | 执行结果临时缓存 |
| 分布式锁 | SET NX + EXPIRE | 防止任务重复执行 |
| 节点心跳 | Key + EXPIRE | 省公司节点在线状态检测 |
| 配置缓存 | String/Hash | 系统配置热更新 |

## 6. 日志存储与检索

### 6.1 选型背景

PRD 6.1 指定 Elasticsearch 用于日志存储和检索，6.3 要求字段标准化遵循 ECS（Elastic Common Schema）。

### 6.2 候选方案对比

| 维度 | Elasticsearch | ClickHouse | Loki |
|------|--------------|------------|------|
| **全文检索** | 原生支持，倒排索引 | 不支持全文检索 | 标签检索，不支持全文 |
| **日志关联** | DSL 查询灵活 | SQL 查询 | LogQL，能力有限 |
| **ECS 兼容** | 原生支持 | 需自行实现 | 无 |
| **安全设备日志** | Filebeat 采集生态完善 | 需自建采集链路 | Promtail 有限 |
| **Kibana 可视化** | 原生 Kibana | 需 Grafana | Grafana |
| **Go 客户端** | go-elasticsearch | clickhouse-go | loki-client |

### 6.3 选型结论：Elasticsearch

**核心理由**：

1. **日志闭环核心**：AttackProbe 日志闭环验证需要将攻击记录与安全设备日志关联匹配，ES 的全文检索和复杂查询能力是核心支撑
2. **ECS 标准**：Elastic Common Schema 提供标准化字段定义，日志解析器输出统一格式后即可入库
3. **Filebeat 生态**：安全设备日志采集（Syslog/CEF/JSON）可直接使用 Filebeat，与 ES 无缝对接
4. **关联查询**：时间窗口 + 五元组 + 特征签名三维匹配查询，ES DSL 原生支持

**版本要求**：Elasticsearch 8.x（改进安全特性、原生向量搜索）

**部署模式**：

| 节点类型 | ES 部署 | 说明 |
|---------|--------|------|
| 集团节点 | 3 节点集群 | 高可用，汇聚全网数据 |
| 省公司节点 | 单节点 | 本地日志存储，资源有限场景 |

## 7. 攻击模拟引擎

### 7.1 选型背景

PRD 6.2 明确基于 Nuclei 模板引擎，MVP 阶段复用其执行能力。同时，为支持更多 ATT&CK 高级技术实现和定制化场景，需评估 Python 作为辅助执行器的可行性。

### 7.2 引擎架构需求分析

| 场景 | Nuclei (YAML) 适用性 | Python 适用性 | 结论 |
|------|---------------------|--------------|------|
| **Web 漏洞扫描** | 擅长，模板丰富 | 可以但无必要 | Nuclei 主导 |
| **网络协议探测** | 擅长，支持多协议 | 可以 | Nuclei 主导 |
| **ATT&CK 高级技术** | 受限，YAML 表达力不足 | 擅长，Impacket/pywinrm 等 | **Python 补充** |
| **横向移动/凭证获取** | 难以实现 | 成熟工具链（Impacket） | **Python 必要** |
| **复杂攻击链编排** | YAML 难以表达条件逻辑 | 灵活的控制流 | **Python 补充** |
| **快速原型/定制** | 改模板 | 写脚本 | Python 更快 |
| **安全研究员上手** | 需学习 YAML 语法 | 普遍熟悉 | Python 更友好 |

**业内产品参考**：

| 产品 | 引擎架构 |
|------|---------|
| 知其安 离朱 | Python + Go 混合 |
| 墨云 Vackbot | 多执行器架构 |
| MITRE Caldera | Python 框架 |
| Atomic Red Team | 多语言（PowerShell/Python/Bash） |

### 7.3 候选方案对比

#### 7.3.1 Nuclei 引擎（Go）

| 维度 | 评估 |
|------|------|
| **语言** | Go |
| **模板格式** | YAML |
| **模板数量** | 10,000+（社区） |
| **嵌入集成** | Go 库直接调用，零开销 |
| **协议支持** | HTTP/TCP/DNS/SSL/Headless 等 |
| **许可证** | MIT |
| **适用场景** | Web 漏洞、网络协议、批量扫描、信息收集 |

#### 7.3.2 Python 执行器

| 维度 | 评估 |
|------|------|
| **版本** | Python 3.9+（兼容性最佳） |
| **调用方式** | 子进程调用，结果通过 JSON 返回 |
| **安全库生态** | Impacket、Paramiko、pywinrm、Scapy 等 |
| **适用场景** | ATT&CK 高级技术、横向移动、凭证获取、复杂攻击链 |
| **信创兼容** | 麒麟 V10 / 统信 UOS 官方源支持 Python 3.9 |

**Python 版本选择依据**：

| 版本 | 安全库兼容性 | 信创系统支持 | 评估 |
|------|-------------|-------------|------|
| 3.11 | 部分老库可能不兼容 | 需手动安装 | 偏激进 |
| 3.10 | 大部分兼容 | 需手动安装 | 可选 |
| **3.9** | 几乎全部兼容 | 麒麟/统信可直接安装 | **推荐** |
| 3.8 | 全部兼容 | 系统默认 | 已 EOL |

**常用 Python 安全库兼容性**：

| 库 | 用途 | 3.9 支持 |
|----|------|---------|
| `impacket` | SMB/WMI/Kerberos 横向移动 | ✅ |
| `paramiko` | SSH 连接 | ✅ |
| `pywinrm` | WinRM 远程执行 | ✅ |
| `scapy` | 网络包构造 | ✅ |
| `pycryptodome` | 加密算法 | ✅ |
| `requests` | HTTP 客户端 | ✅ |
| `ldap3` | LDAP 操作 | ✅ |

## 8. 容器化与部署方案

### 8.1 选型背景

PRD 6.1 指定 Docker + Docker Compose，省公司单机场景适用。PRD 明确不使用 Kubernetes。

### 8.2 候选方案对比

| 维度 | Docker Compose | Kubernetes | 裸机部署 |
|------|---------------|------------|---------|
| **省公司适用性** | 高，单机即可 | 低，至少 3 节点 | 中，手动管理 |
| **运维复杂度** | 低，一条命令 | 高，需专业运维 | 中，脚本管理 |
| **资源占用** | 低 | 高，控制面开销大 | 最低 |
| **服务编排** | 支持，适合 5-10 个服务 | 支持，适合大规模 | 不支持 |
| **信创兼容** | Docker 支持麒麟/统信 | 需额外适配 | 原生 |

### 8.3 选型结论：Docker + Docker Compose

**核心理由**：

1. **省公司单机场景**：31 个省公司 + 23 个专业公司多为单台服务器部署，Docker Compose 单机编排足够
2. **一键部署**：`docker compose up -d` 即可启动全部服务，降低省公司运维门槛
3. **信创兼容**：Docker CE 已支持银河麒麟 V10 和统信 UOS V20
4. **集团节点可扩展**：集团节点如需高可用，可使用 Docker Swarm 做简单集群

**版本要求**：Docker 20+、Docker Compose V2（`docker compose` 子命令形式）

**服务编排规划**：

| 服务 | 容器 | 说明 |
|------|------|------|
| `attackprobe-server` | Go 后端 | 核心服务 |
| `attackprobe-web` | Nginx + 前端静态文件 | Web UI |
| `attackprobe-postgres` | PostgreSQL 16 | 业务数据库 |
| `attackprobe-redis` | Redis 7 | 消息队列/缓存 |
| `attackprobe-es` | Elasticsearch 8 | 日志存储 |
| `attackprobe-filebeat` | Filebeat | 日志采集（可选） |

## 9. 密码算法与安全组件

### 9.1 选型背景

PRD 5.3 要求支持国密算法（SM2/SM3/SM4），同时支持国际通用算法。

### 9.2 算法需求分析

| 场景 | 国际算法 | 国密算法 | 说明 |
|------|---------|---------|------|
| **传输加密** | TLS 1.2+（RSA/ECDSA） | TLCP（SM2/SM3/SM4） | HTTPS 通信 |
| **数据签名** | RSA-2048 / ECDSA | SM2 | API 签名、证书 |
| **哈希摘要** | SHA-256 | SM3 | 密码存储、数据完整性 |
| **对称加密** | AES-256 | SM4 | 敏感数据存储加密 |

### 9.3 Go 国密实现方案

| 库 | GitHub | 说明 |
|----|--------|------|
| `tjfoc/gmsm` | Star 1.8K+ | SM2/SM3/SM4 纯 Go 实现，国内使用最广泛 |
| `emmansun/gmsm` | Star 200+ | tjfoc/gmsm 的 fork，性能优化版 |
| Go 1.19+ 标准库 | 官方 | `crypto/ecdsa` 支持 SM2 曲线（实验性） |

**选型结论**：主选 `tjfoc/gmsm`，理由：
- 纯 Go 实现，无 CGO 依赖，交叉编译无障碍
- 社区活跃，国内 BAS/安全产品广泛使用
- SM2/SM3/SM4 三合一，API 设计清晰

**实现策略**：

```
┌─────────────────────────────────────────────────────────────┐
│                   密码服务抽象层                               │
│     CryptoService interface {                                │
│       Encrypt(data) / Decrypt(data)     // 对称加密          │
│       Sign(data) / Verify(data, sig)    // 数字签名          │
│       Hash(data)                        // 哈希摘要          │
│     }                                                        │
├──────────────────────┬──────────────────────────────────────┤
│  StandardCrypto      │  GMCrypto                             │
│  AES-256 / RSA       │  SM4 / SM2                            │
│  SHA-256             │  SM3                                   │
│  (crypto/*)          │  (tjfoc/gmsm)                         │
└──────────────────────┴──────────────────────────────────────┘
                       ▲
                       │ 配置切换
              crypto_mode: standard | gm
```

通过配置切换密码算法实现，信创环境使用国密，非信创环境使用国际标准算法。

## 12. 技术风险与应对

| 风险 | 可能性 | 影响 | 应对措施 |
|------|--------|------|---------|
| **达梦 DM8 适配工作量大** | 中 | 中 | PG 兼容模式降低适配成本；MVP 先保 PostgreSQL，信创适配 V1.0 完成 |
| **Nuclei 引擎版本升级不兼容** | 低 | 中 | 封装 Executor 抽象层隔离 Nuclei 版本变化；锁定稳定版本 |
| **ES 在省公司资源受限** | 中 | 中 | 提供 ES 单节点最小化配置；评估替代方案（如 OpenSearch）作为后备 |
| **国密算法性能低于标准算法** | 低 | 低 | SM4 性能与 AES 接近；仅在信创环境启用国密，非信创用标准算法 |
| **ARM64 平台第三方依赖不兼容** | 低 | 中 | 所有依赖选择纯 Go 实现（无 CGO），确保交叉编译无障碍 |
