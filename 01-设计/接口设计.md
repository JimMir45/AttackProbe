## 1. 接口规范

### 1.1 基础约定

| 项目 | 规范 |
|------|------|
| 协议 | HTTPS（节点间通信支持 mTLS） |
| 格式 | 请求/响应均为 `application/json` |
| 编码 | UTF-8 |
| 时间 | ISO 8601 格式，如 `2026-01-29T10:00:00Z` |
| ID 策略 | 数据库主键用自增 bigint，业务标识用有意义的字符串 |

### 1.2 认证方式

系统存在三类认证场景：

| 场景 | 认证方式 | Token 有效期 | 颁发时机 |
|------|---------|-------------|---------|
| 用户访问 | Bearer Token (JWT) | 2小时（可刷新） | 用户登录时 |
| 节点通信 | Node Token | 30天（自动续期） | 节点注册时 |
| Agent 通信 | Agent Token | 7天（自动续期） | Agent 注册时 |

**认证头格式：**
```
Authorization: Bearer <token>
```

**Token 刷新机制：**
- 用户 Token：通过 `/common/auth/refresh` 接口刷新
- 节点/Agent Token：每次心跳时检查有效期，剩余 < 7天时在响应中返回新 Token

### 1.3 通用响应格式

**成功响应：**
```json
{
    "code": 0,
    "message": "success",
    "data": { /* 业务数据 */ },
    "trace_id": "req-uuid-12345"
}
```

**错误响应：**
```json
{
    "code": 10001,
    "message": "参数错误：name 不能为空",
    "data": null,
    "trace_id": "req-uuid-12345"
}
```

### 1.4 分页规范

**请求参数：**

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|-----|------|-------|------|
| page | int | 否 | 1 | 页码，从 1 开始 |
| page_size | int | 否 | 20 | 每页条数，最大 100 |
| sort_field | string | 否 | created_at | 排序字段 |
| sort_order | string | 否 | desc | 排序方向：asc/desc |

**响应格式：**
```json
{
    "code": 0,
    "data": {
        "list": [ /* 数据列表 */ ],
        "total": 100,
        "page": 1,
        "page_size": 20
    }
}
```

### 1.5 接口方法约定

| 操作类型 | HTTP 方法 | 路由后缀 | 说明 |
|---------|----------|---------|------|
| 创建 | POST | `/add` | 创建资源 |
| 查询详情 | POST | `/detail` | 传入 ID 查询单条 |
| 分页列表 | POST | `/page` | 带筛选条件分页查询 |
| 更新 | POST | `/update` | 更新资源 |
| 删除 | POST | `/delete` | 删除资源 |
| 批量操作 | POST | `/batch-xxx` | 批量创建/更新/删除 |

> **设计决策**：统一使用 POST 方法，便于传递复杂筛选条件，简化前端调用逻辑。

## 2. 路由架构

### 2.1 两级架构路由设计

基于系统架构设计 4.4 的节点协作机制，API 路由分为两大类：

```
/api/v1/
│
├── 平台管理类（节点间通信）
│   ├── node/                # 节点管理 - 省公司↔集团
│   │   ├── register         # 节点注册
│   │   ├── heartbeat        # 心跳上报
│   │   ├── page             # 节点列表
│   │   └── detail           # 节点详情
│   │
│   ├── agent/               # Agent管理 - Agent↔节点
│   │   ├── register         # Agent注册
│   │   ├── task/fetch       # 任务获取
│   │   ├── result/report    # 结果上报
│   │   ├── offline/export   # 离线包导出
│   │   └── offline/import   # 离线包导入
│   │
│   └── sync/                # 数据同步 - 省公司↔集团
│       ├── case/check       # 用例更新检查
│       ├── case/pull        # 用例增量拉取
│       ├── task/push        # 任务下发
│       ├── result/report    # 结果上报
│       └── result/resume    # 断点续传
│
└── 业务应用类（用户操作）
    ├── bas/                 # 传统BAS应用
    │   ├── target/          # 目标管理
    │   ├── case/            # 用例管理
    │   ├── task/            # 任务管理
    │   ├── result/          # 执行结果
    │   ├── report/          # 报告中心
    │   └── log/             # 日志闭环
    │
    ├── llm/                 # LLM安全应用（V2.0）
    │
    └── common/              # 公共服务
        ├── auth/            # 认证授权
        ├── user/            # 用户管理
        ├── dict/            # 码表服务
        └── system/          # 系统配置
```

## 3. 节点管理 API

> 基于系统架构设计 4.4 节点定义与协作机制

节点管理 API 用于集团节点与省公司/专业公司节点之间的通信。

### 3.1 节点注册

**POST** `/api/v1/node/register`

省公司/专业公司节点启动时向集团节点注册。

```json
// 请求
{
    "node_id": "province_beijing",           // 节点唯一标识
    "node_type": 2,                          // 1=集团 2=省公司 3=专业公司
    "node_name": "北京公司节点",
    "region": "north",                       // 区域：north/south/east/west/central
    "version": "1.0.0",                      // 平台版本
    "capabilities": [2, 3, 6],               // 能力码：2=攻击执行 3=日志采集 6=离线运行
    "network_info": {
        "internal_ip": "10.0.1.100",
        "external_ip": "202.106.x.x",
        "grpc_port": 9000,
        "http_port": 8080
    },
    "hardware_info": {
        "cpu_cores": 8,
        "memory_gb": 16,
        "disk_gb": 500,
        "os": "银河麒麟 V10",
        "arch": "arm64"                      // amd64 | arm64
    }
}

// 响应
{
    "code": 0,
    "data": {
        "registered": true,
        "node_token": "eyJhbGciOiJIUzI1NiIs...",
        "token_expire_at": "2026-03-01T00:00:00Z",
        "group_node_addr": "https://group.attackprobe.cmcc.com",
        "sync_interval": 300,                // 用例同步检查间隔(秒)
        "heartbeat_interval": 30,            // 心跳间隔(秒)
        "config": {
            "log_level": "info",
            "max_concurrent_tasks": 50
        }
    }
}
```

### 3.2 心跳上报

**POST** `/api/v1/node/heartbeat`

省公司/专业公司节点定期向集团上报心跳和状态。

```json
// 请求
{
    "node_id": "province_beijing",
    "timestamp": "2026-01-29T10:00:00Z",
    "status": {
        "running_tasks": 5,                  // 当前运行任务数
        "queued_tasks": 10,                  // 队列中任务数
        "completed_today": 150,              // 今日完成数
        "executor_status": {
            "nuclei": {
                "status": 1,                 // 1=ready 2=busy 3=error
                "workers": 50,
                "active_workers": 25

                "status": 1,

                "active_workers": 3
            }

        {"agent_id": "agent_dmz_01", "status": 1, "running_jobs": 5},
        {"agent_id": "agent_prod_01", "status": 2, "running_jobs": 0}
    ]

// 响应

```

## 4. Agent 管理 API

Agent 管理 API 用于节点与其下属 Agent 之间的通信。

        "hostname": "dmz-agent-01",
        "ip": "10.0.2.100",
        "os": "CentOS 7.9",
        "arch": "amd64"
    }

{
